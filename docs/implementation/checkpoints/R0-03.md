## Decisions

- Keep OpenAI Symphony's App Server workflow and replace its weak line-buffered
  process boundary with focused `Codex.Connection`, `JSONLFramer`,
  `RequestPolicy`, `StderrDiagnostics`, `TransportError`, and
  `ProcessAdapter` components. No Studio persistence or UI is required to run
  the core engine.
- Treat stdout as protocol-only JSONL and stderr as a separate bounded
  diagnostic channel. Decode only complete frames, permit messages beyond the
  upstream one-megabyte line boundary, cap decoded frames at a configurable
  16 MiB default, and bound queued messages, queued bytes, server requests,
  completed IDs, outbound frames, and the content-free stderr suffix
  projection. Raw stderr and hashes are never retained.
- Initialize exactly once, wait for the matching response, then send
  `initialized`. Enforce one pending synchronous request, exact response IDs,
  duplicate/unexpected-response rejection, terminal-delivery acknowledgement,
  and absolute monotonic deadlines so a late mailbox response cannot win.
- Retry App Server overload `-32001` only for the explicit idempotent-read
  allowlist, with bounded exponential backoff and jitter. Handshake requests
  fail rather than retry; side-effecting and unknown requests are never blindly
  repeated.
- Create a canonical request hash and in-memory prepared operation envelope
  before `thread/start`, `turn/start`, `review/start`, reset-credit consumption,
  and conservative tool mutations. Once transmission may have occurred, a
  timeout, connection loss, late successful tool result, or response-write
  failure becomes `uncertain_external_outcome`. The durable operation ledger
  and post-crash reconciliation reducer remain explicitly owned by R1-07.
- Persist a small, `0600`, source-identity-bound compatibility-circuit marker
  beneath the configured workspace root after App Server protocol corruption.
  Automatic dispatch stays blocked for that Codex/schema/manifest identity and
  clears only after the identity changes and the replacement manifest records
  green transport conformance.
- Reject all Release 5 remote-worker configuration in Release 0 before SSH,
  process launch, retry reconciliation, or hot-reload dispatch. A stale local
  workflow cannot bypass this gate after reloading to a remote configuration.
- Vendor the complete `erlexec` 2.3.4 source distribution as an offline Mix
  path dependency. Its two downstream changes are build-only: safe relative,
  quoted native-output paths and removal of publisher/documentation plugins.
  The complete upstream license remains verbatim in the vendored `LICENSE`;
  root `NOTICE` reproduces its copyright notice, all three conditions, and
  disclaimer.
- Launch the candidate-controlled App Server argv and per-attempt containment
  chain without shell evaluation; the containment launcher/target bootstrap
  receives an empty environment. Probe util-linux `unshare` before every launch
  and require its user/PID/mount namespace, current-user map, proc mount, fork,
  and kill-child behavior. The long-lived vendored `exec-port` starts through
  erlexec's upstream trusted-runtime boundary and is not a user-job child.
- Use a two-stage startup barrier. Before target code runs, capture the stopped
  outer process-group leader and anchor, then the stdin-blocked exact PID-
  namespace root, then its stdin-blocked exact PID 2 target. Validate PID start
  times, parentage, process group/session, `NSpid`, and PID-namespace inode at
  each boundary. Only then deliver the bounded target environment and release
  the executable.
- Put the target in a namespace-local session, make trusted PID 1 non-dumpable,
  and keep its exact PID/start-time identity as independent cleanup authority.
  Forced cleanup pidfd-signals that root before the anchored outer group;
  success requires the linked manager, original group, and namespace root all
  to be absent. Linux PID-namespace-init teardown is the transitive cleanup
  proof for ordinary, `setsid`, nested, TERM-resistant, and daemonizing
  descendants.
- Publish the captured PID 2 as `codex_app_server_pid`; retain the outer
  wrapper, root, group, session, and start-time identities only as private
  diagnostics. Public cleanup scope is `local_pid_namespace`, not a mislabeled
  wrapper PID or process-group-only claim.
- Bind `fixtures` and `transportConformance` to the same manifest lifecycle:
  both `not_run`, both `under_test`, or both `pass`. Keep
  `runtimeCapabilities=not_run` and `overall=pending_r0_06`; R0-03 does not
  manufacture live account/model/quota evidence.

## Supported platform boundary

The Release 0 local reference profile is Linux x86_64. In addition to the
R0-02 requirements, R0-03 requires:

- util-linux `unshare` with working `--user --map-current-user --pid --fork
  --kill-child=SIGKILL --mount-proc`;
- enabled unprivileged user namespaces and a nonzero user-namespace limit;
- procfs process identity, parent/child, `NSpid`, and namespace-inode data;
- Python 3.10 or newer with `os.pidfd_open`,
  `signal.pidfd_send_signal`, isolated `-I -S` startup, and libc `prctl` through
  `ctypes`; and
- ordinary unprivileged erlexec operation. SUID, user-switching, Linux
  capability, and privileged resource-control modes are not enabled. No
  WORKFLOW or user-job field controls erlexec's helper; the runtime accepts
  only its exact bundled helper or a trusted operator-preconfigured absolute,
  regular, executable `:erlexec, :portexe` path.

The implementation host is Debian 12 x86_64, Linux 6.1.0-49-amd64,
util-linux 2.38.1, and Python 3.11.2. Its unprivileged-user-namespace switch is
enabled, `user.max_user_namespaces=128229`, the exact unshare probe passes, and
both required pidfd Python APIs are present. Other Linux hosts must pass the
same probe and live pinned-Codex smoke. Supplementary group IDs can render
differently inside a user namespace; operations that manipulate group identity
need separate compatibility evidence, while ordinary host permission checks
remain in force.

## Acceptance plan

1. Force compile with warnings as errors, format, public-spec check, Credo,
   Dialyzer, and `git diff --check`.
2. Run ProcessAdapter, Connection/stderr, AppServer, compatibility-circuit,
   framer, request-policy, fake App Server, config/workspace, AgentRunner,
   Orchestrator, and status suites at deterministic seeds 0 and 42.
3. Exercise owner crash, timeout, anchor loss, ptrace, PID reuse, inner
   process-group signaling, hostile `setsid` descendants, exact environment,
   loader controls, and no-orphan-at-return paths against real Linux processes.
4. Run the fixed source-bound schema/transport fixture suite, recompute its
   exact nonzero test count, and run the Python schema-tool suite.
5. Verify the installed Codex pin and deterministic schema regeneration.
6. Start the pinned real Codex App Server through the production adapter,
   complete only `initialize` / `initialized` plus metadata inspection, close
   it, and prove wrapper/root/target cleanup. Do not call `thread/start` or
   `turn/start` and do not consume model quota.
7. Seal fixtures with `python3 scripts/codex_schema.py seal-fixtures
   --tested-at 2026-07-16`, then verify the committed manifest and its exact
   source/test bindings.
8. Run `cd elixir && mise exec -- make all` and package/archive,
   credential, absolute-path, symlink, ignored-build-artifact, and provenance
   checks.
9. Obtain independent read-only review of the final source and sealed evidence,
   rerun any affected gate, then commit and push the accepted package without
   updating `main`.
