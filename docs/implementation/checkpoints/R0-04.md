## Decisions

- The existing App Server callback remains additive and continues to expose
  `event` and `timestamp`. The structured sink normalizes those fields to
  `type` and `occurred_at`; no upstream callback field is renamed or removed.
- `run_id` is created when a logical issue run is first admitted and is retained
  across continuation and failure retries until the claim is released.
  `attempt_id` is created only when an actual worker attempt starts. Scheduler
  timer, tracker, workflow-validation, and capacity deferrals may change the
  existing integer retry `attempt`, but never manufacture an execution attempt.
- `operation_id` is created before a logical external operation is prepared and
  remains stable across transport request-ID changes, bounded idempotent-read
  retries, acknowledgement, failure, and uncertainty. It is an additive,
  optional top-level field on the version-1 event envelope and a safe public
  metadata field where an event describes one operation. It does not replace
  JSON-RPC `request_id`, the canonical request hash, or a future durable ledger.
- A producer assigns each immutable event envelope once. Its UUID event ID is
  deterministically bound to run ID, per-run sequence, and normalized event
  type; a legitimate repeated event therefore receives a new sequence and a
  distinct ID. Redelivery and replay reuse the full original envelope.
- Ordering is defined by a positive monotonic sequence per run, never wall-clock
  time. Exact duplicates converge without consuming a sequence or updating a
  projection. Reused IDs or sequences with conflicting content fail closed.
- R0 provides an injected no-op sink and a bounded, process-local memory adapter
  with per-run FIFO event retention, deterministic run eviction by oldest
  successful new-event append, and explicit replay-unavailable and replay-gap
  results. Replay and duplicate access do not refresh eviction order. The sink
  is observability, not scheduler authority: optional sink unavailability or
  lost history is fail-open after a sanitized diagnostic, while an invalid
  envelope or true conflicting redelivery is rejected and cannot advance the
  current projection.
- Normalization consumes only existing allowlisted public callback data. Prompt
  bodies, issue descriptions, credentials, raw stderr, unrestricted provider
  frames, and private reasoning are not event payloads.
- Structured stream-head cursors remain separate from the existing legacy
  `recent_events` projection, so a replayable stale-attempt event cannot be
  presented as the current attempt's legacy callback.

## Changed surfaces

- New generic boundaries: `SymphonyElixir.Identity`, `SymphonyElixir.Event`,
  and `SymphonyElixir.EventSink` with Noop and Memory adapters.
- Core integration: Orchestrator, AgentRunner, Codex Connection, and Codex
  AppServer lifecycle and operation correlation.
- Additive observability: Presenter state/issue projections retain every
  existing field and add run, attempt, and stream-head cursors.
- Contract evidence: focused identity/event/sink/orchestrator tests plus
  operation, uncertainty, callback, scheduler, and API regressions.

## Acceptance plan

- Prove UUID generation/validation and deterministic event identity without a
  new runtime dependency.
- Prove the canonical version-1 envelope, JSON-safe bounded payload, UTC time,
  normalized type, truthful redaction marker, and optional operation
  correlation.
- Prove isolated per-run sequences, exact duplicate idempotency, conflict
  rejection, ordered replay, empty replay at head, deterministic bounded
  eviction, and typed gaps/unavailable history.
- Propagate run and attempt IDs through Orchestrator admission, running entries,
  AgentRunner callbacks, retry metadata, blocked entries, late blockers,
  snapshots, and additive `/api/v1/*` fields.
- Assign operation IDs in prepared Connection and App Server operations before
  transmission; prove identical calls differ and overload wire retries retain
  the same logical ID without exposing parameters.
- Re-run the raw-data redaction canaries and existing scheduler/API compatibility
  suites, then reseal the source-bound fixture manifest and both independent
  test-count oracles.
- Run targeted tests first, then randomized fixture replay, schema verification,
  `cd elixir && mise exec -- make all`, exact no-model compatibility smoke,
  archive hygiene, and independent review.

## Remaining release boundary

- SQLite schema/migrations and durable event persistence belong to R1-01 and
  R1-02.
- Persist-before-broadcast projections, restart/browser reconnect replay, and
  Studio event routes or UI do not belong to R0-04.
- The durable operation ledger, crash-window reconciliation reducer, claims,
  tracker outbox, and completion synchronization remain R1-07.
- Cancellation/workspace/managed-tracker hardening remains R0-05; live
  capability discovery and readiness completion remain R0-06.
- Remote workers, provider abstractions, and Release 2+ product surface remain
  out of scope.
