- Package goal: harden cancellation and retry convergence, bind cleanup to

  gate; no-model compatibility smoke; archive hygiene; and independent review.

## Decisions

- Upstream mode remains the default. It retains the root specification's raw
  single-operation Linear query-or-mutation behavior. R0-05 fixes the existing
  violation that forwarded multi-operation documents.
- Managed tool policy is designed as an explicit AppServer option until R1-03
  owns `studio.enabled` and dynamic configuration. It uses a real GraphQL
  parser, a bounded document, one operation, an explicit read-root allowlist,
  trusted issue/run context, and fail-closed denial of raw mutations. Rejected
  documents and transport bodies are never copied into diagnostics. AppServer
  and AgentRunner both default to upstream mode; only an explicit internal
  `managed: true` option selects the seam before R1-03 adds Studio configuration.
- Deterministic managed lifecycle requests use a validated immutable command
  envelope and an injected outbox sink. A missing sink fails closed. R0-05 does
  not persist, retry, reconcile, or claim confirmation; SQLite and the durable
  outbox reducer remain R1-01 and R1-07.
- A configured workspace root may itself be a symlink and is canonicalized
  once. An issue leaf may never be a symlink, including a link to a sibling
  under the same root. Sanitization preserves ordinary identifiers and adds a
  collision-resistant suffix whenever byte replacement or truncation is
  required.
- Active and retry cleanup use the immutable canonical workspace path recorded
  by the attempt, never a path recomputed from a hot-reloaded root. A missing
  binding preserves the workspace instead of guessing. Startup cleanup remains
  scoped to the current configured root.
- Cancellation first retires the worker and its App Server containment, then
  runs `after_run`/`before_remove`, and only then removes a terminal workspace.
  Unverified retirement or cleanup must preserve the workspace and safety
  claim. The exact workspace binding is published before any hook starts, and
  hook-cleanup uncertainty propagates through every lifecycle phase.
  A cooperative cancellation error or timeout is never followed by a
  synchronous `Task.Supervisor.terminate_child/2`: the controller may own the
  only cleanup authority and uses infinite shutdown. Orchestrator instead
  records a typed safety block, retains the live controller PID, and charges it
  against global, immutable admitted-state, and worker-host capacity until the
  PID exits. Tracker refresh may update the issue snapshot but cannot move that
  retained capacity to another state. Terminal turn events clear the active
  interrupt target so a completed turn cannot cause a stale interrupt block.
- The `:one_for_all` runtime containment domain starts, in order, a registered
  `CleanupBarrier`, `CleanupSupervisor`, direct `ConnectionSupervisor`, hook
  supervisor, agent-task supervisor, and Orchestrator. Reverse shutdown leaves
  both cleanup barriers available while Connections, hooks, and AgentRunners
  retire. CleanupBarrier also monitors each established Connection,
  AgentRunner, and WorkspaceHookRunner lifetime, protecting the same boundary
  if a nested Connection/Task/WorkspaceHook supervisor is killed. A runtime
  child is not replaced until every registered member retires and every
  retained cleanup handle is durably verified. Runtime restart intensity is
  bounded to 10 restarts in 5 seconds.
- A CleanupGuardian acknowledges readiness only after it traps exits and
  monitors its owner. Its handle preserves verification state independently of
  guardian liveness, so the cleanup registry, AgentRunner, and hook runner can
  distinguish verified late exit from lost authority. A Task.Supervisor start
  error or exit after invocation is ambiguous because the child may already
  exist: CleanupGuardian waits for the exact ready token, adopts that child if
  it acknowledges, and otherwise holds fail closed forever. Only positively
  observed non-start or known child absence can transfer authority toward
  caller-owned cleanup. `CleanupBarrier` and `CleanupSupervisor` are reciprocal
  shutdown barriers if either one crashes.
  Ordinary established-Connection teardown has one physical-stop authority:
  Connection delegates its first request to
  `CleanupGuardian.request_cleanup_once/2`, and only the guardian's bounded
  worker invokes `adapter.stop`. A successful result verifies cleanup; an error
  commits `cleanup_authority: :guardian`. Later close, owner-down,
  supervisor-exit, child-exit, failure, and terminate paths cannot start a
  second stop. The established guardian handle is published before Connection
  readiness, and its shared durable status is marked verified before either a
  successful cleanup reply or Connection notification is emitted. A dead
  Connection is not considered retired until that handle proves cleanup.
  Barrier-registration loss does not create a second cleanup caller: the
  acknowledged guardian remains sole owner while `CleanupSupervisor` exists;
  if both runtime authorities are absent, guardian cleanup must become durably
  verified before startup raises and a caller may enter inline fail-closed
  cleanup. Lost unverified authority blocks instead of falling through.
- Every retry-entry removal cancels its timer before deleting state. Stale
  tokens remain harmless, backoff retains upstream continuation semantics, and
  R0-05 does not introduce the durable R1 circuit breaker.
- Local hooks run with an explicit environment contract, bounded redacted
  output, and the verified local process-containment primitive. Hook timeout or
  cancellation cannot race lifecycle progress or leave unowned descendants.
  A dedicated supervisor remains available while agent tasks drain, and a hook
  runner retains cleanup authority after an unverified stop. Newly created
  partial workspaces are rolled back after a failed bootstrap; reused
  workspaces are never reset.
- All public remote Workspace operations fail with the existing Release-5
  feature-gate error before SSH. Dynamic workflow validation classifies that
  failure as `failure_kind=unsupported_release_feature`; it neither labels the
  failure as a tracker fetch nor logs the feature/release tuple. R0-05 does not
  implement remote containment.
- Relative workspace roots resolve against the selected `WORKFLOW.md`
  directory, and every consumer receives the same normalized absolute root.
- Default sandbox policy remains an explicit issue-workspace writable root
  with network disabled. Managed policy narrows unsafe explicit variants;
  schema-level parsing and default upstream behavior remain compatible.

## Changed surfaces

- Implemented Class A cancellation/retry hardening: `RuntimeSupervisor`
  couples registered `CleanupBarrier`, `CleanupSupervisor`, direct
  `ConnectionSupervisor`, hook and agent task supervisors, and the in-memory
  Orchestrator under `:one_for_all`. CleanupBarrier and CleanupSupervisor hold
  reciprocal restart barriers around durable, ready-acknowledged
  CleanupGuardian handles. Ambiguous Task.Supervisor start results wait for and
  adopt only the token-matched ready guardian; ambiguity without acknowledgement
  never returns inline authority. CleanupBarrier additionally registers and
  monitors Connection, AgentRunner, and WorkspaceHookRunner lifetimes,
  providing the reciprocal barrier when a nested supervisor is killed. Runtime
  restart intensity is bounded to 10 restarts in 5 seconds. Connection traps
  its supervisor exit; normal established-Connection cleanup delegates even its
  first physical stop to `CleanupGuardian.request_cleanup_once/2`, so
  Connection never invokes `adapter.stop`. A failed delegated attempt commits
  guardian authority, all subsequent teardown entry points return
  cleanup-in-progress, and startup rollback remains owned by a ready guardian,
  waits forever on unresolved start ambiguity, or transfers only after guardian
  absence is positively observed.
  AgentRunner and WorkspaceHookRunner monitor retained handles and accept late
  exit only when durable status proves cleanup. AgentRunner also owns a
  cooperative cancellation controller; AppServer exposes `turn/interrupt`;
  and Orchestrator waits for verified worker, connection, and hook retirement
  before `after_run`, `before_remove`, exact-bound deletion, claim release, or
  retry. A failed or timed-out cooperative cancellation is preserved as a
  nonblocking safety hold whose live controller continues to consume global,
  admitted-state, and worker-host capacity. Established Connection cleanup
  authority is published before readiness and verified before cleanup success
  becomes observable. Terminal turn events clear the interrupt target.
  Lifecycle events share one sender per hook generation, and every retry-entry
  removal cancels its timer.
- Implemented Class A workspace/hook hardening: `Workspace`, `PathSafety`,
  `WorkspaceHookRunner`, `Workflow`, and `Config.Schema` now provide
  workflow-relative canonical roots, deterministic collision-resistant issue
  leaves, direct-child and symlink denial, root-bound removal, explicit hook
  environment/output/process limits, fresh-workspace rollback, reused-workspace
  preservation, pre-hook exact-binding publication, and managed exact-root
  sandbox narrowing. Remote workspace entry points remain release-gated before
  SSH.
- Implemented the Class A root-contract repair in `DynamicTool`: pinned
  Absinthe AST parsing now enforces exactly one raw upstream query or mutation
  while retaining the existing raw high-trust behavior for that one operation.
- Implemented the Class B managed seam: option-selected `DynamicTool` policy
  binds a bounded read allowlist to trusted issue/run context;
  AppServer/AgentRunner carry that context; `Tracker.ManagedMutation` validates
  immutable lifecycle commands; and `Tracker.Outbox` delegates once to an
  explicitly injected sink with out-of-band Studio provenance. It has no
  default sink or durability.
- Documentation now classifies the source changes and records security and
  deferral boundaries. The final source-bound compatibility seal, Build Week
  delta reconciliation, hygiene audit, reproducible package construction, and
  independent exact-tree reviews all pass.

## Resolved review decisions

- Lifecycle-hook cleanup uncertainty is now a typed safety blocker in
  `after_create`, `before_run`, `after_run`, and `before_remove`. The attempt
  publishes its exact path/root before hooks, cancellation waits for the
  supervised runner, and Orchestrator preserves the claim/workspace without
  retry on any unverified result.
- Startup rollback no longer depends on a live Connection or worker to retain
  authority. The ready-acknowledged handle is registered outside the guardian's
  owning task supervisor, and CleanupBarrier/CleanupSupervisor provide
  reciprocal shutdown barriers. A Task.Supervisor error/exit after the start
  call is ambiguous, not proof of absence: the token-matched ready child is
  adopted, and no acknowledgement leaves the starter in a permanent safety
  hold. Only observed non-start can transfer authority. Separately, post-ready
  CleanupBarrier registration failure is single-owner: it cannot make a
  guardian stop and caller inline stop overlap, and inline fail-closed cleanup
  is reachable only after the prior guardian is durably verified. AgentRunner
  and hook retention treat an unverified guardian exit as lost authority and
  hold indefinitely rather than reopening lifecycle or restart progress.
- The prior P2 test gap for the no-acknowledgement branch is resolved. Its
  regression returns an ambiguous starter error without creating a guardian
  child,
  waits beyond the ready timeout, and proves the caller remains held while the
  runtime generation is unchanged, adapter stop count and maximum concurrency
  remain zero, and no inline fallback occurs. This resolves the focused oracle
  gap; the complete final-tree gates and independent package reviews pass.
- Final review found and repaired four additional cancellation/retirement
  races: synchronous termination of an infinite-shutdown retained controller,
  lost capacity accounting after cancellation timeout and tracker state
  refresh, a successful guardian reply preceding durable verification, and a
  stale terminal turn ID. Regressions prove reconciliation remains responsive,
  the claim/workspace and all three capacity limits remain fail closed until
  controller exit, guardian proof precedes cleanup success, and terminal turn
  events remove the interrupt target.
- The seed-42 fixture replay exposed a test-only supervisor-loss ordering race.
  The regression now monitors the old `CleanupSupervisor` and awaits its exact
  `:DOWN` before releasing Connection, preserving the intentional permanent
  ambiguous-start hold while making the expected known-absence path
  deterministic. The repaired case passed 25 repeat-until-failure iterations,
  the complete 15-test runtime suite, and independent review.
- The mandatory pre-push full gate at seed `375551` exposed a separate P2
  diagnostic-classification defect: the live default Orchestrator observed the
  process-global remote workflow installed by another test, then the generic
  failure fallback mislabeled typed workflow validation as a tracker-fetch
  failure and raw-inspected its tuple. A dedicated Orchestrator clause now emits
  only the stable unsupported-feature classification. The targeted two-test
  replay and 25 repeat-until-failure iterations pass; the broader core/workspace
  slice passes 124 tests in 18.4 seconds; and the exact seed-`375551` complete
  coverage replay passes 535 tests, zero failures, two skips, and 100.00%
  measured coverage in 283.2 seconds.
- Ordinary cleanup uses the same single-owner rule. Connection delegates even
  the first physical stop to `CleanupGuardian.request_cleanup_once/2` and never
  invokes `adapter.stop`; the first failed delegated result commits guardian
  authority before any later lifecycle message can be handled. Explicit close,
  owner death, ConnectionSupervisor exit, adapter child exit, failure
  convergence, and `terminate/2` therefore cannot create a second stop caller.
- CleanupBarrier protects more than guardian handles. Connection registers
  before process launch, AgentRunner before spawning its attempt worker, and
  WorkspaceHookRunner before publishing its started event. If any corresponding
  nested supervisor is killed, the barrier retains the trapped member lifetime
  and prevents predecessor/replacement coexistence. The runtime's 10-restarts-
  in-5-seconds intensity bound also prevents unbounded restart churn.
- Direct AppServer and normal AgentRunner calls remain upstream by default.
  Managed policy requires explicit `managed: true`; R1-03 will own the first
  product configuration that selects it.
- Local removal still uses userspace pathname revalidation rather than a
  descriptor-relative removal syscall. For v0.1.0 this is inside the declared
  one-trusted-local-operator and non-hostile-same-UID boundary: all untrusted
  candidate, App Server, and hook processes are retired first, issue leaves are
  direct non-symlink children, and path/root identity is revalidated around the
  final hook. Multi-user/same-UID hostile operation is not a Release 0 claim;
  Release 5 is the first team expansion. A violation of that deployment
  boundary is unsupported configuration, not a waived release-blocking defect.
