## Exact-version decisions

- The installed authority is user-local `$HOME/.local/bin/codex` at
  `codex-cli 0.144.3`. Global executable drift does not change the pin.
- The generated schema controls wire shape. `account/rateLimits/read` and
  optional `account/usage/read` omit `params`; sending an empty object is not
  treated as equivalent.
- App Server is initialized exactly once per discovery connection, followed by
  the paramless `initialized` notification. Capability discovery does not call
  `thread/start` or `turn/start`.
- `model/list` is paginated to a null cursor with explicit page, item, and
  repeated-cursor bounds. Reasoning efforts and service-tier IDs remain opaque
  runtime strings; no literal tier or silent downgrade is assumed.
- `account/read.account.type=apiKey` and
  `account/updated.authMode=apikey` normalize to one canonical mode. Legacy
  `getAuthStatus` is excluded because it can expose a raw token.
- Codex 0.144.3 supplies no opaque stable account ID. Raw email is never
  persisted or emitted. A ChatGPT binding therefore uses a domain-separated
  keyed digest held only in local protected state plus a local generation;
  when identity evidence is absent or cannot prove sameness after auth change,
  the result fails closed and requires explicit confirmation.
- The generated App Server schema and `model/list` response do not expose a
  per-session multi-agent cap or the model's multi-agent selector. The pinned
  Codex source and the installed model-cache evidence agree that both required
  reference models select MultiAgentV2. That model selector overrides the
  disabled V2 feature flag, so the legacy `agents.max_threads` setting is not
  the reference-profile authority.
- For MultiAgentV2,
  `features.multi_agent_v2.max_concurrent_threads_per_session` includes the
  root: raw values `1`, `2`, and `3` map to zero, one, and two concurrent
  non-root threads. The exact installed parser accepts those isolated
  run-profile values without a model turn. The legacy V1 setting excludes the
  root, and is retained only as a conservative compatibility ceiling.
- Codex 0.144.3 MultiAgentV2 does not enforce `agents.max_depth`; a pinned
  behavioral test proves a direct child can spawn a grandchild with
  `max_depth=1`. Discovery therefore reports
  `native_depth_enforcement=false` and
  `studio_depth_guard_required=true`. A bounded Studio `PreToolUse` hook now
  proves the intended root/direct-child behavior when it executes, while a
  separate conformance case proves hook execution failure is fail-open. The
  hook is a permanent Class B defense-in-depth boundary, not a temporary Class
  C patch and not the sole authorization layer. R1-05 still owns deterministic
  admission and interruption around this exact limitation.
- Static schema presence, deterministic fakes, and live values are separate
  evidence states. A required live value or behavioral cap that is not proven
  keeps the readiness result blocked.
- The pinned upstream `WORKFLOW.md` carried an OpenAI-specific Linear project
  binding that is not visible in the fork owner's downstream workspaces. The
  authorized downstream runtime binding now selects the dedicated validation
  project while preserving Linear as tracker of record, the existing active
  states, and all five terminal names including both `Cancelled` and
  `Canceled`. Only that project slug and generic state names are public.
  Protected runner authentication remains process-local, and no read-only
  capability result authorizes a comment or state mutation.
- Linear may resolve the configured URL-style project selector while returning
  only its terminal `slugId`. Discovery accepts that result only when the
  returned value is identical to the configured selector or its exact non-empty
  hyphen-delimited suffix; every other result blocks as a binding mismatch.
