## Decisions

- Pin `codex-cli 0.144.3`, the exact installed build used for this package.
- Record both npm identities without conflating them: the published platform
  version is `@openai/codex@0.144.3-linux-x64`, while the local optional-
  dependency alias is `@openai/codex-linux-x64`.
- Retain raw generator output. Codex's aggregate V2 JSON schema varies only in
  object-member order between clean generations, so JSON is compared through a
  documented semantic canonical hash while TypeScript is compared byte for
  byte. Reordering generated JSON in place would obscure provenance.
- Generate both stable and `--experimental` JSON/TypeScript trees. Experimental
  presence is compatibility evidence, never an undeclared runtime dependency.
- Keep R0-02 static schema presence separate from R0-06 live account, model,
  effort, tier, quota, identity, event-emission, and multi-agent-cap probes.
- Validate production outbound requests against the pinned generated contract.
  The `initialized` notification has no invented `params`, `turn/start` has no
  unadvertised `title`, dynamic tools declare `type: function`, dynamic-tool
  responses expose only `success` plus `contentItems`, and approval policy
  accepts only the pinned string or boolean-granular shapes. The legacy
  `reject` map is normalized to the current `granular` representation with
  fail-closed defaults. `never` is not an authorization grant: unexpected
  approval callbacks receive only schema-defined denials, permission requests
  receive an empty grant, and actual user-input requests remain blocked.
- Validate thread and turn sandbox values before App Server launch. Thread mode
  is limited to the pinned enum; explicit turn policies are exact tagged
  variants with type-checked values and normalized absolute writable roots.
  The default policy contains no generated-schema extension, and a remote
  relative workspace cannot reach the wire.
- Use a strict ordered stdio App Server fixture that matches method and request
  ID rather than answering by input-line count. Its versioned scenarios and
  deterministic traces will be reused for R0-03 transport/process conformance.
- Use a stateful Bandit service bound to an ephemeral loopback port for fake
  Linear. This exercises the real Req/GraphQL client and adapter without a
  production-only seam, global fake-client module, or external network access.
- Generated ordinary test workflows use the memory tracker by default. Tests
  that assert Linear semantics must opt into the loopback fixture; only the
  separately gated live E2E path may name the production Linear endpoint.
- Seal fixture compatibility only after the fixed focused suite and full
  candidate verification pass. The pre-test manifest is marked `under_test`,
  is stored outside the worktree, and is rejected by the ordinary verifier.
  The exact focused suite executes from a private source/schema snapshot with
  a fresh build path; only a separately constructed and verified post-test
  manifest may replace the committed manifest. One external process lock
  serializes bundle readers and writers, and directory/file identity fences
  prevent a stale rollback from overwriting a newer bundle. The seal binds the
  exact test count and command, date, Codex/artifact/schema/matrix hashes, and a
  text-LF/binary-raw hash of all compile/runtime sources, including static
  assets, while preserving the independent schema-generation date.

## Changed surfaces

- Root Codex version/lock and deterministic schema tooling.
- Raw generated stable/experimental JSON Schema and TypeScript bundles,
  manifest, checksums, method/field matrix, provenance README/NOTICE, and a
  package-safe runtime loader.
- Strict ordered fake App Server scenario runner and focused integration tests.
- Stateful loopback fake Linear service and real client/adapter integration
  tests, including commit-then-error uncertainty.
- Network-hermetic test workflow defaults, explicit live-E2E opt-in, and the
  static schema check in `make all`.
- Narrow production compatibility fixes for pinned App Server request shapes,
  dynamic-tool typing, and approval-policy validation/normalization.
- Test-only JSON Schema validation through Xema 0.17.9 and deterministic
  supervised WorkflowStore ownership recovery between tests.
- The R0-02 schema/fixture gate requires Linux x86_64, Python 3.10 or newer,
  procfs, child-subreaper and pidfd support, inotify, `renameat2` exchange,
  no-follow descriptor opens, and durable file/directory `fsync`. Xema 0.17.9
  and its transitive `conv_case` 0.2.3 dependency are test-only, MIT-licensed
  inputs; comprehensive SBOM and third-party-notice packaging is deferred to
  the R0-07 release gate.

## Open boundary

- Transport separation, frame limits, timeout/retry rules, uncertain
  side-effect reconciliation, and process-group cleanup are R0-03 acceptance
  work. R0-02 builds a fixture capable of proving those behaviors; it does not
  prematurely claim the current adapter conforms.
- Runtime compatibility remains `pending_r0_06` until bounded live discovery
  establishes the authenticated account and installed App Server capabilities.
